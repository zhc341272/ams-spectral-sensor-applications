# 故障排查

[English](TROUBLESHOOTING.md) · [返回中文首页](../README.zh-CN.md)

## 看不到串口或串口打不开

- 插好 USB 后点“刷新”，并在 Windows 设备管理器确认主板串口存在。
- 关闭 STM32CubeIDE 串口终端、其他串口工具和旧的上位机进程。
- 波特率保持 115200，重新插拔主板。
- Python 报 `PermissionError` 通常说明串口正被其他进程占用。

## 出现 `UNKNOWN_ID` 或旧版的 unknown address

已知地址有应答、身份寄存器不匹配时，固件报告 `UNKNOWN_ID`。依次执行：

```text
I2CSCAN
DIAG
AS CONFIG
```

查看应答地址、`ID_RAW`、`ID_CODE`、`SIG92`、`SIG5A`、`SIGCFG0`、`SIGD6`、SCL/SDA 电平和 HAL I²C 错误。

- `0x39` 有 ACK 且符合 AS7341 身份：大概率属于 AS7341 数字协议族。
- `0x39` 有 ACK 且 `0x5A=0x81`：符合 AS7343 数字协议族。
- `0x59` 有 ACK 且 `0x5A=0x81`：在当前支持器件中高度符合 TCS3448。
- 有 ACK 且稳定读到另一个 ID：核对丝印和数据手册。
- ID 数值来回变化：优先检查焊接、去耦、上拉和 I²C 信号完整性。

## I²C 扫不到任何地址

按以下顺序排查：

1. 传感器封装脚上的电源和地；
2. 芯片方向与 1 脚标记；
3. SCL/SDA 通断和短路；
4. 上拉电阻以及空闲时是否为高电平；
5. 当前器件要求的复位/使能脚；
6. 封装引脚是否真正兼容；
7. 连锡、虚焊、焊盘翘起或过热损伤。

AS7341 在板上能工作，可以证明共用的 `0x39` 总线和部分封装连接正常，但不能单独证明 AS7343 所有专用引脚条件都满足。

## 能识别，但采样失败

- 先执行 `AS FORCEINIT`，再执行 `AS SAMPLE FORCE`。
- 查看 `INFO`/`DIAG` 中的 `INIT_BUSY_WARN`、`STATUSX`、`I2CERR` 和饱和标志。
- 做过原始寄存器写入后重新断电上电。
- 除非有独立证据确认光学版本，否则恢复 `AUTO` 配置。
- 切换配置后确认上位机收到了新的 `CHANNELS` 报文。

## 净值为零、扣暗后为负或重复性差

上位机会把负的 `亮场 − 暗场` 截成 0。可在“全部通道数据”或 CSV 中查看原始值。

- 亮场采集时确认只有当前 LED 真正点亮。
- 检查 `board_config.h` 中 LED 有效电平。
- 暗场和亮场之间环境光变化大时，加强遮光。
- 确认点亮、熄灭稳定延时没有从 50 ms 降低。
- 暂时使用固定增益，区分自动增益问题和光路问题。

## 出现饱和标志

降低固定增益、ATIME/ASTEP、LED 电流或光耦合强度。自动增益最多预采样四次，如果最低实用增益仍然饱和，也无法恢复已经截顶的数据。饱和数据不适合做定量比较。

## 一轮四光源测量感觉较慢

每一路包含增益预采样、暗场积分、亮场积分和两次 50 ms 稳定等待。需要提速时：

- 确定安全参数后关闭自动增益；
- 在计数仍够用的前提下降低积分时间；
- 不要直接缩短稳定延时，除非在实际 LED 驱动和光学腔上做过重复性对比。

## 中英文切换后文字没有变化

重新选择另一种语言。中文图表出现方框时，安装微软雅黑或 Noto Sans CJK SC 后重启。

## 固件不能编译

- 导入 `firmware/stm32g030`，不要把仓库根目录当 CubeIDE 工程。
- 确认工程名为 `ams_spectral_sensor_firmware`。
- 工具链选择 STM32CubeIDE 自带的 GNU Tools for STM32。
- 旧依赖文件还指向历史绝对路径时，先清理工程。
- 确认链接脚本 `STM32G030C8TX_FLASH.ld` 仍在工程根目录。
