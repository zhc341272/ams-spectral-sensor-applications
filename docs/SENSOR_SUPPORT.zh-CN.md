# 传感器识别与通道说明

[English](SENSOR_SUPPORT.md) · [返回中文首页](../README.zh-CN.md)

## 固件如何识别

驱动不会只看到 ACK 就下结论。它会检查预期地址和只读身份寄存器，探测后恢复寄存器 Bank，并同时上报寄存器协议族与可能的订货型号。

| 识别结果 | 使用的证据 | AUTO 默认配置 |
|---|---|---|
| AS7341 family | `0x39` 有 ACK；`0x92 >> 2 == 0x09` | AS7341 |
| AS7343 family | `0x39` 有 ACK；切换 Bank 后 `0x5A == 0x81` | AS7343 |
| TCS3448 | `0x59` 有 ACK；切换 Bank 后 `0x5A == 0x81` | TCS3448 |
| `UNKNOWN_ID` | 已知地址有 ACK，但身份值不符合 | 无 |
| `NONE` / I²C 错误 | 两个支持地址都没有有效 ACK | 无 |

在 `0x39` 上，固件先检查 AS7341 的只读身份寄存器，再尝试 AS7343 风格的 Bank 读取，避免把 AS7341 的 `0xBF` 错当成另一套寄存器含义。

## 为什么精确料号仍可能有歧义

AS7341 与 AS7341L 共用数字身份族；AS7343 与 AS7343L 也可能共用地址和 ID，但光学通道解释不同。因此固件把两件事分开：

- **识别协议族 / 候选型号：** 来自真实器件的数字证据；
- **实际解析配置：** 用来给原始 ADC 槽位标注通道名称的映射。

`AUTO` 默认使用普通 AS7341 或 AS7343 映射。只有芯片丝印、料盘标签或采购记录能确认 `L` 版本时，才应手动选择对应配置。手动选择后，上位机仍保留原来的候选型号，不会把操作员选择冒充为新的硬件证据。

## 遇到意外芯片时怎么判断

- `0x39` 有 ACK 且符合 AS7341 ID，只能说明当前焊接和共享地址接口支持 AS7341，不能单独证明 AS7343 的全部引脚条件。
- `0x39` 有 ACK 且 `0x5A == 0x81`，支持 AS7343 数字协议族，但未必能区分 AS7343 与 AS7343L。
- `0x59` 有 ACK 且 `0x5A == 0x81`，在当前支持集合中高度符合 TCS3448。
- `UNKNOWN_ID` 表示地址确实有应答，但身份模式不认识。修改识别条件前应先保存 `DIAG` 输出。
- 完全没有 ACK 时，应先查供电、复位、上拉、焊接、方向、封装引脚和总线电平，而不是先猜新的 ID。
